# 角色、摘录与回忆

本页介绍如何围绕一款游戏沉淀三类"细节资料"：从平台拉取的**角色档案**、自己记录的**台词摘录**，以及以 MDX 文章形式保存的**游玩回忆**。三者都挂在游戏详情之下，但数据形态和用途不同：角色是结构化元数据，摘录是短文本条目，回忆是带 frontmatter 的长文。

> 首次使用请先完成[安装与配置](/zh/guide/intro/installation-and-configuration)，并把游戏加入[游戏库](/zh/guide/feats/game-library)。角色同步依赖外部平台，相关凭证见[平台接入与资料更新](/zh/guide/feats/platforms)。

## 功能全景

| 能力       | 入口                               | 主要数据          | 典型用途                 |
| ---------- | ---------------------------------- | ----------------- | ------------------------ |
| 角色同步   | 游戏详情 → 相关人物 → 角色同步设置 | `character` 表    | 批量导入角色立绘与档案   |
| 角色档案   | 角色卡片 → 角色详情                | 结构化字段 + 图片 | 查看身高、生日、关联台词 |
| 台词摘录   | 顶栏「摘录」/ 游戏详情 → 摘录      | `game_quote` 表   | 收藏经典台词、导出 XLSX  |
| 回忆       | 游戏详情 → 回忆                    | MDX + frontmatter | 写长篇游玩记录、配乐回放 |
| 回忆元数据 | 设置 → 回忆                        | 设置文件          | 自定义字段与图标         |

## 整理角色资料

### 同步流程

1. 打开目标游戏的详情，切到「相关人物」标签。
2. 点击「角色同步设置」，在弹窗中选择**数据来源**。当前内置的角色数据源有 VNDB、Bangumi 和 YMGal 三个。
3. 核对或填写该平台对应的**游戏 ID**。vnweb 会优先从 `game_id_map` 表中查找本地游戏与该平台的映射；找不到时才需要手动输入。
4. 按需勾选「将角色图片保存到本地」。勾选后角色立绘会被下载到本地资源目录，随备份一起保存；不勾选则保留远程图片链接。
5. 点击「保存」开始同步，等待角色卡片出现。

::: tip ID 从哪里来
VNDB 角色 ID 形如 `c123`，作品 ID 形如 `v184`。如果此前通过[平台接入](/zh/guide/feats/platforms)用 VNDB 搜索并添加了游戏，`game_id_map` 会自动写入映射，同步角色时通常无需手动填 ID。
:::

### 同步后的角色档案

每个角色条目保存以下结构化字段：

| 分组 | 字段                                                  | 说明                                   |
| ---- | ----------------------------------------------------- | -------------------------------------- |
| 标识 | `name` / `original`                                   | 角色译名与原文名                       |
| 简介 | `description`                                         | 平台返回的人物介绍                     |
| 外观 | `imageUrl`                                            | 立绘地址或本地路径                     |
| 身体 | `height` / `weight` / `bust` / `waist` / `hips`       | 身高（cm）、体重（kg）与三围           |
| 资料 | `bloodType` / `age` / `birthdayMonth` / `birthdayDay` | 血型、年龄、生日                       |
| 分类 | `sex` / `gender`                                      | 生理性别与社会性别，值为 JSON 文本     |
| 去重 | `vndbId`                                              | 与 `gameId` 组成唯一索引，避免重复同步 |

点击角色卡片进入详情，可以看到该角色关联的台词摘录——前提是摘录时选择了对应角色。

### 角色数据源的差异

| 数据源  | 特点                                 | 注意事项                                                                                              |
| ------- | ------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| VNDB    | 角色字段最完整，支持三围、生日等细节 | 需要配置 API 地址；Token 仅用于写入类操作（详见[平台接入](/zh/guide/advanced/platform-integrations)） |
| Bangumi | 中文条目覆盖较好                     | 同步前会校验角色列表响应结构，异常时不会写入                                                          |
| YMGal   | 国产 Galgame 资料补充                | 需要对应账号凭据                                                                                      |

::: warning 同步是覆盖而非合并
同一 `(gameId, vndbId)` 的角色会被更新。如果手动修改过角色简介，再次同步可能覆盖你的改动。重要内容建议同时记录在回忆中。
:::

## 添加和导出台词

### 新建摘录

1. 从顶栏进入「摘录」，或打开游戏详情中的「摘录」标签。
2. 点击「添加摘录」，填写台词内容 `content`，并关联游戏 `gameId`。
3. 如果角色资料已经同步，可以在「角色」字段指定对应角色，之后可从角色详情反向查看。
4. 可选：填写 `context`（上下文），记录这句台词出现前的剧情背景。
5. 保存后，用搜索框和游戏/角色筛选即可查找。

### 摘录的存储形状

```sql
-- game_quote 表的关键字段（摘自 db/schema.ts）
id          INTEGER PRIMARY KEY AUTOINCREMENT
gameId      INTEGER NOT NULL
content     TEXT    NOT NULL
characterId TEXT    DEFAULT ''   -- 关联 character.id
context     TEXT    DEFAULT ''
createdAt   TEXT    DEFAULT ''
updatedAt   TEXT    DEFAULT ''
```

`characterId` 使用文本类型保存，兼容"未关联角色"的空字符串情况。

### 导出 XLSX

在全局「摘录」页点击「导出 XLSX」，选择要包含的游戏和导出方式后会生成表格文件。底层使用 ExcelJS 在服务端生成工作簿。

- **按游戏导出**：勾选指定游戏，适合整理单一作品的台词本。
- **按条件导出**：结合搜索关键词与创建时间筛选，适合做主题摘录集。
- **桌面端**：在 Tauri 桌面端导出时会调用原生「另存为」窗口，可自行指定保存路径。

也可以通过 AI 助手的 `export_quotes_xlsx` 工具完成同样的筛选与导出，详见 [AI 助手与 WebMCP](/zh/guide/feats/ai-assistant)。

## 写游玩回忆

回忆是一种带 Markdown 正文和 frontmatter 元数据的文章，适合记录较长的感想、路线复盘或剧情笔记。

### 新建与编辑

1. 打开「游戏详情 → 回忆」，点击新建。
2. 填写标题和正文。正文支持 Markdown，例如：

   ```md
   ## 由岐视点

   走到海边时才明白，那段反复出现的独白并不是预告，而是回响。

   > 我们所谈论的"日常"，究竟是谁的日常？
   ```

3. 上传截图。Markdown 图片的文本（`alt`）会自动作为图注展示。
4. 按需关联 OST 曲目并开启自动播放。要选曲，先在 [PV 与 OST](/zh/guide/feats/media) 中整理好对应歌曲。
5. 保存后点开条目阅读。窄屏下目录会显示在文章上方，宽屏下显示在左侧。

回忆表单是限宽限高的可滚动弹窗，长文不会影响页面布局。列表支持统一批量删除，误删风险较高的操作会有二次确认。

### frontmatter 元数据

回忆的附加信息保存在 Markdown frontmatter 中，编辑器表单与文件双向同步：

```yaml
---
title: 第一次通关的那天
description: 关于 Summer Pocket 的一点记录
tags:
  - 感想
  - 一周目
date: 2026-03-14
---
正文从这里开始。
```

- 内置一组博客常用元数据字段（带图标）。
- 在「设置 → 回忆」可以维护**自定义元数据**，例如「游玩平台」「个人评分」，并选择字段图标。
- 回忆图片作为独立备份分类参与本地备份、ZIP 导出和远程同步，详见[备份、恢复与同步](/zh/guide/feats/save-backup)。

::: tip MDX 渲染
回忆详情页使用 MDX 渲染。正文里可以混用标题、引用、图片与自定义组件。历史上 `<center>` 嵌套在 `<p>` 内会引发 Hydration 报错，现已修复；写作时仍建议优先使用标准 Markdown 语法。
:::

## 与平台资料的关系

角色同步和平台资料共用同一套 ID 映射机制：

1. 通过平台搜索导入游戏时，写入 `game_id_map(provider, externalId)`。
2. 游戏信息中的 `externalSourceIds` 也会保留各平台的外部 ID。
3. 角色同步时先按 `(gameId, provider)` 解析外部 ID，再调用对应 provider 拉取角色列表。
4. 拉取到的字段被归一化为统一的 `NormalizedCharacterRow`，再写入 `character` 表。

这层映射让用户既能从游戏找到平台条目，也能从平台条目反查本地游戏。状态推送（游玩状态同步到 Bangumi / VNDB）则复用同一映射，详见[平台接入与 WebMCP](/zh/guide/advanced/platform-integrations)与[启动与游玩记录](/zh/guide/feats/play-records)。

## 排错

| 现象               | 可能原因                           | 处理                                  |
| ------------------ | ---------------------------------- | ------------------------------------- |
| 角色同步后列表为空 | 游戏 ID 填错，或该平台没有角色数据 | 回到同步设置核对 ID；换一个数据源尝试 |
| 角色图片显示为破图 | 远程图床限制，或本地化下载失败     | 勾选「保存到本地」重新同步；检查网络  |
| 角色详情看不到台词 | 摘录未关联该角色                   | 编辑摘录并指定角色                    |
| 导出 XLSX 为空     | 当前筛选条件下没有条目             | 清除搜索词或改选游戏                  |
| 回忆正文渲染异常   | 使用了非标准 MDX 标签              | 改为标准 Markdown 语法                |
| 回忆元数据丢失     | 编辑器未保存或备份恢复覆盖         | 检查 frontmatter；从备份中找回旧版本  |

::: danger 数据边界
vnweb 默认把资料库与游玩记录留在本地。外部平台只用于读取元数据或推送状态，是否上传数据取决于你在平台设置中的显式操作。模型与第三方服务的处理范围见 [AI 助手与 WebMCP](/zh/guide/feats/ai-assistant)。
:::
