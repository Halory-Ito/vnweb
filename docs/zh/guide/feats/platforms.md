# 平台接入与资料更新

扫描能建条目，但封面、简介、角色、收藏和游玩状态来自外部平台。这一篇把五个平台的用途、字段、更新策略和安全边界讲清楚；建库的基础操作见[扫描与游戏库](./game-library)，媒体来源见[PV 与 OST](./media)。

## 配置平台

打开「设置 → 平台」，启用需要使用的平台，再按界面填写凭证。查询公开资料、读取个人收藏和推送游玩状态使用的权限可能不同，个人功能需要先绑定账号。

![游戏详情页展示，显示封面、游玩时长以及角色、OST、记录等标签](/overview.png)

### 平台总览

| 平台        | 配置方式与用途                                                                                                                    | 是否需要账号          |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------- | --------------------- |
| Steam       | 配置 Steam Web API Key，绑定 Steam 账号后可导入拥有的游戏，并在账号卡片中使用「同步游戏时长」。读取库存需要账号公开相关游戏资料。 | 导入库存/同步时长需要 |
| Bangumi     | 按页面提示填写个人访问令牌。使用镜像时一并核对所选接口来源。绑定后可读取收藏并推送状态。                                          | 读取收藏/推送需要     |
| VNDB        | 使用 VNDB 令牌绑定账号。根据所需操作授予读取列表或修改列表的权限。                                                                | 读取/修改列表需要     |
| YMGal       | 配置 Client ID 和 Client Secret 查询月幕资料。需要读取账号收藏时，按页面提示绑定用户 ID。                                         | 读取收藏需要          |
| SteamGridDB | 配置 API Key 后，可用于补充封面、背景、图标和徽标等图片。                                                                         | 仅 Key                |

::: tip 公开资料与个人数据分开看
只查询作品信息（标题、简介、封面、角色）通常不需要绑定账号；读取「我的收藏」或把游玩状态推回平台才需要授权。先按用途决定配哪些凭证，避免过度授权。
:::

### 配置文件长什么样

平台配置会保存到 `data/settings/platform.json`，示例位于 `data/example/platform.json`。核心字段如下：

```json
{
  "steam": { "apiKey": "" },
  "bangumi": {
    "useMirror": false,
    "mirrorUrl": "",
    "baseUrl": "",
    "tokenUrl": ""
  },
  "vndb": {
    "baseUrl": "https://api.vndb.org/kana",
    "oauthToken": "",
    "oauthScope": ""
  },
  "ymgal": {
    "baseUrl": "https://www.ymgal.games",
    "clientId": "",
    "clientSecret": ""
  },
  "steamgriddb": {
    "apiKey": "",
    "baseUrl": "https://www.steamgriddb.com/api/v2"
  },
  "meting": { "bitrate": 320, "coverSize": 300, "neteaseCookie": "" },
  "enhanced": {
    "useLocalSdk": false,
    "apiBase": "https://music.163.com/api",
    "musicU": "",
    "quality": "standard",
    "sdkPort": 3001
  }
}
```

::: danger 不要把这份文件公开
API Key、访问令牌、`neteaseCookie`、`musicU` 都是个人凭证。不要提交到公开仓库、不要贴进 Issue 或截图；备份时也要确认存放位置是私密的。
:::

## 逐个平台说明

### Steam

**用途**：导入拥有的游戏、补充作品资料，以及从「设置 → 平台」的 Steam 账号卡片发起时长同步。

**配置要点**：

- 填写 Steam Web API Key。
- 绑定 Steam 账号后使用个人功能。
- 读取库存需要账号公开相关游戏资料；如果库存为空，先检查隐私设置。

**更新策略**：库存导入是一次性拉取；已导入条目仍可按名称或平台 ID 更新资料。时长同步适合定期手动执行，不要在短时间内反复触发。

::: warning 隐私设置
Steam 库存与游戏时长受账号隐私设置影响。vnweb 读不到数据时，先确认账号资料已按你的预期公开，再排查 Key 是否有效。
:::

### Bangumi

**用途**：读取收藏、按条目补资料、把游玩状态推送回 Bangumi。

**配置要点**：

- 按页面提示填写个人访问令牌，而不是 OAuth 客户端配置。
- 使用镜像时，一并核对所选接口来源与令牌获取地址；`useMirror`、`mirrorUrl`、`baseUrl`、`tokenUrl` 要匹配同一套服务。
- 绑定后可读取收藏并推送状态。

**更新策略**：资料更新按条目 ID 匹配更稳；状态推送前先检查本地状态与 Bangumi 状态的映射关系，见下方[同步游玩状态](#同步游玩状态)。

### VNDB

**用途**：查询视觉小说资料、角色与封面，读取/修改个人列表，推送游玩状态。

**配置要点**：

- 使用 VNDB 令牌绑定账号。
- 按所需操作授予读取列表或修改列表的权限；只查询公开资料时不必申请写入权限。
- `baseUrl` 默认是 `https://api.vndb.org/kana`，可按需调整。

**更新策略**：按平台 ID 匹配比按名称搜索更准确；同一作品存在多条 VNDB 记录时，结合发售日与开发商核对。

::: warning Token 权限
写入状态需要对应权限。如果推送失败，先确认令牌的 scope 包含所需操作，再重试。
:::

### YMGal

**用途**：查询月幕（YMGal）资料与封面；绑定用户后可读取账号收藏。

**配置要点**：

- 配置 `clientId` 与 `clientSecret` 用于查询资料。
- 需要读取账号收藏时，按页面提示绑定用户 ID。
- `baseUrl` 默认是 `https://www.ymgal.games`。

**更新策略**：与 VNDB 类似，优先用平台条目 ID 关联；资料更新结果要核对版本，避免把不同版本的信息混在一起。

### SteamGridDB

**用途**：补充封面、背景、图标和徽标等图片。

**配置要点**：只需 API Key；`baseUrl` 默认 `https://www.steamgriddb.com/api/v2`。

**更新策略**：图片属于可重复获取的派生数据。对已经手工替换过封面或背景的条目，更新前先确认是否要覆盖。

### OST 相关：Meting 与 Enhanced API

严格说它们不是「资料平台」，但同在平台设置里，这里一并说明。`meting` 配置读取码率、封面尺寸与网易云 Cookie；`enhanced` 配置本地 SDK 调用方式、API 地址、`musicU`、音质与端口。字段细节见[PV 与 OST → 导入与播放 OST](./media#导入与播放-ost)。

## 导入收藏与更新资料

1. 要把平台收藏加入本地库，打开「游戏库 → 添加菜单 → 从第三方导入」，选择来源并勾选要导入的游戏。
2. 要给已有条目补资料，在游戏详情的右键菜单中选择「更新资料数据」，按游戏名或平台 ID 查找对应条目。核对版本和名称，再应用搜索结果。
3. 要单独维护图片、匹配平台条目或修改可执行路径，打开游戏详情的「设置」。第三方条目导入后，如需启动本地安装的游戏，在这里核对可执行路径。

::: tip 导入与更新的区别
**导入**解决「库里还没有」；**更新**解决「库里已有但资料不全」。两者都可能改动封面与元数据，但都不会自动帮你填好可执行路径。
:::

批量维护多款游戏时，回到[游戏库 → 整理游戏库](./game-library#整理游戏库)使用批量操作；导入结果的后续启动设置见[启动与游玩记录](./play-records#启动游戏并计时)。

## 同步游玩状态

在「设置 → 平台」为 Bangumi 或 VNDB 绑定账号，检查本地状态与平台状态的映射。在游戏详情编辑游玩状态，通过对应的平台入口选择或确认条目后保存。Steam 的时长同步从「设置 → 平台」的 Steam 账号卡片发起。

### 状态映射怎么用

本地的游玩状态（例如「想玩」「正在玩」「已通关」「搁置」）与平台的状态集合不一定一一对应。项目允许在对应平台的设置区配置**多对一映射**：多个本地状态可以映射到同一个平台状态。

```text
本地状态 → 平台状态映射 → 平台条目 → 推送结果
```

::: warning 先关联条目，再推送
推送前先在游戏详情里通过搜索或输入 ID 关联平台条目。没有关联时，平台端不知道你指的是哪部作品。
:::

### 推送结果怎么看

关联与推送记录会按游戏持久化，方便你检查某条状态是否已经同步。外观设置中可以自定义四种推送状态的指示点颜色；具体样式以当前版本界面为准。

## 速率限制与失败处理

外部平台通常都有频率限制或临时故障。下面是比较稳妥的做法：

1. **先小批量后大批量**：先更新一款试试，确认凭证和匹配规则正确，再处理多个条目。
2. **失败时稍后重试**：平台读取出错时，界面通常会给出错误提示与重试入口；不要连续高频点击。
3. **错开平台**：不同平台的限制互相独立，Steam 同步失败不影响 Bangumi 资料更新。
4. **保留原始配置**：配置读取失败时不要直接删文件，先检查 JSON 格式与字段类型；项目会校验字段类型与端口范围。
5. **核对接口来源**：Bangumi 使用镜像时，`baseUrl` 与令牌地址要一致；按月幕资料时确认 `baseUrl` 指向你实际使用的站点。

::: danger 不要共享凭证
不要把 Key、Token、Cookie 借给别人或在公共机器上保存。需要多人协作时，各自申请自己的凭证。
:::

## 账号与 Cookie 安全提示

- 平台凭证保存在本机 `data/settings/platform.json`，请按私密文件对待。
- 网易云 `neteaseCookie` / `musicU` 与账号权限等价，泄露后应及时在对应平台失效处理。
- 排查问题时截图要脱敏：遮住 Key、Token、Cookie、用户名和用户 ID。
- 备份设置文件时，确认备份目标（含 WebDAV / S3 远端）同样是私密存储；见[备份、恢复与同步](./save-backup)。
- 不使用某平台时，可以清空它的凭证，减少暴露面。

## 常见问题

### 配置保存后立即失效

平台配置可能优先读取浏览器缓存。保存后刷新页面再确认；如果仍不对，检查 `data/settings/platform.json` 的字段类型。

### 搜不到条目

先确认平台已启用、凭证有效；再尝试用平台 ID 而不是名称搜索。名称含中文、日文或括号版本时，搜索结果可能不稳定。

### 库存/收藏为空

检查账号隐私设置与授权范围；Bangumi 镜像场景下核对 `baseUrl` 与 `tokenUrl` 是否指向同一来源。

### 状态推送失败

确认令牌具备写入权限、平台条目已关联、映射关系符合预期。详见[同步游玩状态](#同步游玩状态)。

### 图片更新把我的封面覆盖了

更新资料会写入图片字段。手工替换过封面时，更新前先确认要覆盖；也可以更新后重新设置。

## 小结

- 公开资料查询通常不需要账号；个人收藏与状态推送才需要授权。
- Steam 管库存与时长，Bangumi / VNDB 管收藏与状态，YMGal 管月幕资料，SteamGridDB 管图片。
- 匹配优先用平台 ID；批量更新前先小范围验证。
- 凭证属于个人数据，备份与截图都要脱敏。
