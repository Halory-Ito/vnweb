# 什么是 vnweb

**vnweb 是面向数字文化的开源、本地优先、Agent 原生基础设施。** 它从视觉小说与本地单机游戏出发，将本地文件、社区元数据、媒体内容与游玩记录整合进可自托管资料库，并通过 WebMCP 与可交互生成式 UI 探索用户掌控下的人机协同管理。

> 日常管理与 AI 协作使用 Web UI，快速启动游戏用 CMD；若希望像普通软件一样运行，还提供基于 Tauri 的桌面端。未来演进与 AI 研究方向见[公开路线图](/zh/roadmap)。

## 它到底解决什么问题

如果你只有三五款游戏，文件夹其实够用。但当本地视觉小说堆到几十上百款时，文件夹开始暴露出几个问题：

- **找不到**：只记得「那个谁写的、封面是蓝色的」，却记不清具体名字。
- **认不全**：下载回来的目录名可能是乱码缩写，封面、开发商、角色一概没有。
- **记不住**：玩过多少小时、上次推到哪、哪条线已经通关，全靠脑补。
- **散落各处**：攻略在网页收藏夹，OST 在音乐软件，回忆在聊天记录，存档在另一个盘。

vnweb 想做的是把这些碎片收进**一个可自托管的资料库**：游戏是主体，封面与元数据、角色、PV、OST、攻略、台词摘录、回忆、游玩记录都挂在它周围。

## 适用人群

::: tip 你可能会喜欢 vnweb，如果……

- 你玩视觉小说或本地单机游戏，而且资源是**自己保存在电脑里**的。
- 你希望资料尽可能全，愿意花一点时间配置平台凭证来换自动刮削。
- 你在意界面细节：字体、背景、边框、布局都想自己调。
- 你想知道「我这些年到底玩了多少小时」，并且愿意回头看报告。
  :::

反过来，下面几种期待可能不太适合：

- 想要一个云端同步、多端即开即玩的 SaaS：vnweb 默认是本机运行、本机数据。
- 只想管理 Steam 游戏库而不放本地文件：直接用 Steam 客户端更省事。
- 希望装上就自动识别所有破解版/汉化版的奇葩目录名：扫描仍需你确认规则与结果，见[扫描与游戏库](../feats/game-library)。

## 和同类工具的比较

下面是我自己的使用感受，不是客观评测。工具都在变，建议按当下版本亲自试一试。

| 工具         | 我当时喜欢的地方                                       | 当时觉得不够的地方                                               |
| ------------ | ------------------------------------------------------ | ---------------------------------------------------------------- |
| **PotatoVN** | 第一次发现「原来还有这种软件」，而且用起来方便         | 可定制化太低，我对样式有点挑剔                                   |
| **Vnite**    | 好看很多，支持的功能也非常丰富                         | 垂类信息还是不够，恨不得做成 wiki；还有几个小bug让我有点接受不了 |
| **vnweb**    | 把资料、媒体、攻略、记录和外观放在同一个可自托管的库里 | 还在成长，部分能力与平台接口仍依赖社区与上游服务稳定             |

我并不想「打败」谁。做 vnweb 的初衷是：如果现有的工具差一点满足我，那就自己把那一点补上。

## 工作流概览

一旦 setup 完成，日常循环其实很短：

```text
扫描/导入 → 补齐资料 → 设置可执行路径 → 启动并记录 → 查看统计 → 整理内容 → 备份
```

1. **录入**：扫描本地目录，或手动添加、从第三方平台导入。
2. **补全**：配置平台后更新资料数据、图片与角色。
3. **启动**：确认可执行路径，开始游戏；退出后会话自动落库。
4. **回顾**：在总览、月报、年报里看趋势，或打开单款游戏的「记录」。
5. **沉淀**：写回忆、摘录台词、整理攻略、补 PV 和 OST。
6. **保存**：做本地备份，或同步到 WebDAV / S3。

每一步都有对应的文档：从[第一次使用](#第一次使用)的清单出发，按需跳到[功能指南](#核心能力全景)表格里的页面。

## 三类使用入口

### Web UI：日常主力

浏览器访问本机服务（开发模式默认 `http://localhost:3000`，生产/启动模式默认 `http://localhost:8999`）。扫描、刮削、统计、主题设置、备份等都在这里完成，是功能最完整的入口。

### CMD：快启动与批处理

根目录的 `vnweb.bat` 是命令入口：无参数时启动 Web 服务，带参数时进入命令行模式。适合搜索游戏、列收藏夹、启动最近玩过的那款。

```sh
vnweb list game
vnweb search 白色相簿
vnweb start 12       # 启动并计时，按 q 结束
vnweb start          # 快速启动最近一次游玩的游戏
```

::: warning 路径以本机为准
命令行启动要求可执行文件是**本机绝对路径**。游戏搬盘后，先在[游戏详情 → 设置](../feats/game-library#整理游戏库)里更新路径。更多命令见[命令行工具](../feats/other)。
:::

### 桌面端：像普通软件一样打开

仓库包含基于 Tauri v2 的桌面壳：Windows x64 安装包提供单实例管理、系统托盘，并通过原生窗口选择可执行文件与存档目录。桌面端与 Web 端共享同一份用户数据目录；相关构建脚本见[安装与配置](./installation-and-configuration#方式三-tauri-桌面端)。

## 第一次使用

1. 按照[安装与配置](./installation-and-configuration)启动 vnweb，并打开 Web 界面。
2. [扫描本地游戏目录或手动添加游戏](../feats/game-library)。如果需要补齐封面、角色或其他资料，再[配置相应平台](../feats/platforms)。
3. 打开游戏详情，设置可执行路径并[开始游戏](../feats/play-records)。第一次退出后，可以在该游戏的「记录」里查看时长。
4. 按需要[维护攻略](../feats/walkthroughs)、[整理回忆与摘录](../feats/game-notes)或[开启存档备份](../feats/save-backup)。

想要一条更紧凑、带命令示例的操作路径，直接读[快速开始：5 分钟从零到玩](./quick-start)。

## 缘起

主播是在2024年入坑的视觉小说，第一部是《饿殍》，推了70%吧，但是由于一些原因，耽搁了好久，后来就没有玩了。

接着是《fsn》，情况类似，因为没有看攻略，也没有频繁 save 的习惯，推到后面好像只剩下 be 了，也没有玩下去了。

然后是《素晴日》，久仰大名哇，但是**当时**序章还没推完呢，感觉一般吧，也没有继续推下去了。

第一部推完的应该是《弹丸论破1》，感觉很 nice，画风也很有特色，这时才感受到视觉小说的魅力。

于是陆陆续续推完了《素晴日》、《弹丸论破2》、《魔法使之夜》等有口碑的视觉小说，一发不可收拾。

现在回头看，那段经历其实解释了这个项目的很多细节：为什么要做攻略与路线进度？因为当年没看攻略，推到后面只剩 be。为什么要记录时长和最近游玩？因为中断太多次，再捡起来时总想先知道「我上次玩到哪」。为什么要给每款游戏留一块写回忆的地方？因为有些故事推完之后，是真的想说点什么。

## 为什么要做这个

随着本地视觉小说的资源越来越多，管理起来有点不够优雅，因为面对的全是文件夹，和视觉小说画风不符。

一开始我是使用的其他视觉小说管理软件，先是 PotatoVN，起初我是震惊的，原来还有这种软件，而且用起来还方便，但缺点就是可定制化太低了，我对样式有点挑剔。

后来接触了 Vnite，这个就好看很多了，并且支持的功能也非常丰富，但是还是不够，如果要对视觉小说进行管理的话，那就应该尽量支持其各种垂类信息，恨不得做成 wiki 的程度；此外，也存在几个小bug，让我有点接受不了。

因此，一方面对开发这类项目有兴趣，另一方面要搞毕设了，而毕设选题我可以自己决定，于是就开整了。

> 题外话：毕设答辩的时候被拷打了，"你这个项目对国家、社会有什么意义?"，"这个可是毕设啊，你做这个项目就为了更好地打游戏?"，🥲

## 设计哲学

### 数据回流到本地

平台是来源，不是归宿。刮削结果、角色、图片最终都写进本地库；你可以断网继续使用已经导入的资料。相关约定见[API 与数据层](/zh/guide/advanced/api-and-data)。

### 可定制但不打断

外观设置提供字体、背景、毛玻璃、主题色、无边框等选项，但默认配置开箱可用；改设置时尽量只刷新相关区域，避免「动一点、整页重渲染」。见[外观与主题](../feats/custom-theme)。

### 让内容彼此关联

游戏不是孤立条目：角色、PV、OST、攻略、回忆、摘录都挂在它下面，同时也能在全局页面浏览。这种关联是[架构总览](/zh/guide/advanced/architecture)里的核心概念。

### 对外部内容保持谨慎

导入的元数据、攻略和回忆属于第三方内容。Agent 读取这些内容时需要权限边界与用户确认，这也是公开路线图里明确写下的安全目标；见[平台接入与 WebMCP](/zh/guide/advanced/platform-integrations)与[关于](/zh/about)。

## 路线图指引

上表中的本地优先底座已在 `v0.2.2` 落地。结合仓库 [ROADMAP.md](https://github.com/Halory-Ito/vnweb/blob/main/ROADMAP.md)，后续演进分成两条主线：

- **游戏库体验**：CG 画廊、按每次启动选择补丁的补丁管理。
- **叙事与 Agent 研究**：多模态叙事理解、语义知识图谱、按游玩进度防剧透的 GraphRAG、带结构化预览与确认的 Agent 工作流，以及隐私安全评估。

这些是研究和计划方向，不是版本承诺。完整说明请看[公开路线图](/zh/roadmap)、[关于 → 接下来准备做什么](/zh/about#接下来准备做什么)与[更新日志](/zh/guide/advanced/changelog)。

## 小结

- vnweb 是**本地优先**的视觉小说/单机游戏资料库，不是云盘，也不是纯启动器。
- 它把扫描、刮削、启动计时、统计、媒体与内容整理串成一条工作流。
- 三种入口并存：Web UI 管日常，CMD 管快启动，桌面端管「像软件一样打开」。
